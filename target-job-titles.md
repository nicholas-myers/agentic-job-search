Primary targets
These match your resume, stack, and the level your manager described at the senior promotion:

Software Engineer
Full-Stack Software Engineer / Full-Stack Engineer
Application Developer / Web Application Developer (common in .NET and public-sector postings)
Use these for most applications and for LinkedIn Open to Work.

Strong secondary targets
Use when the posting matches how you actually worked:

.NET Developer / .NET Software Engineer when C# and backend work are central
React Developer / Frontend Engineer when the role is mostly React/TypeScript
Software Engineer II or Software Engineer 2 on leveled ladders (often mid-level)
Selective stretch
Apply when the description fits your recent ownership, not only the title:

Senior Software Engineer when the bar is roughly 3–5 years, end-to-end feature ownership, and production systems—not title inflation
Consultant / Software Engineer (contract) for consulting-style delivery and client-facing work
Lower priority
Programmer/Analyst / Programmer Analyst — accurate for some government and consulting employers, but weaker for recruiter search; use only when the team and stack are clearly engineering
Backend Engineer / Frontend Engineer alone — fine as add-ons, not your main lane unless you want to specialize
Usually skip for now
Principal, Staff, Lead, and Architect unless you have explicit scope (team leadership, system design across teams, multi-year ownership).

How to run the search
Lead with Software Engineer and Full-Stack; add .NET or React when the post emphasizes one stack. Treat Senior as a fit check on responsibilities, not a default target. In government and consulting, also watch Application Developer and Programmer Analyst when the work is clearly full-stack engineering.

Practical split: most volume on mid-level full-stack and software engineer roles; a smaller set of senior postings where you can point to migrations, upgrades, reporting refactors, and cross-stack delivery.
